# 交互拼装编辑器设计（子项目 2）

日期：2026-09-02
状态：已确认（用户逐节过目）
关联：`2026-08-27-desktop-app-design.md`（范围拆分第 2 项）

## 1. 定位与范围

让玩家在 3D 视口里**手动拼装**舰船：从部件面板拖部件进来、移动/旋转/缩放、删除、选面开槽。吸附系统自动对齐，玩家不碰曲线、不手动对边缘。手动操作与 AI 指令共享同一棵 OpTree——手动摆的布局，AI 看得懂、改得动。

本期**不含** AI 演算补形（下一迭代）、外部模型导入（子项目 3）。

## 2. 架构与数据流

手动操作**不经过 LLM**，纯确定性路径：

```
视口操作 → POST /api/edit → 翻译成 OpTree 变更 → pydantic + DAG 校验
（与 LLM 产出同一套 _validate）→ 增量构建（缓存生效）→ 返回新树 + 重渲染
```

LLM 会话与手动编辑读写同一个 session 文件。这保证"手动/AI 统一"：玩家拖出来的 attach_part 节点，AI 下次接到指令时直接在其上修改。

吸附计算放在**服务端纯函数**：前端只发原始坐标/面信息，Python 侧算吸附结果返回。吸附逻辑因此可 pytest 覆盖，无需浏览器测试。

## 3. 手动操作 → OpTree 映射

| 玩家操作 | OpTree 变更 |
|---|---|
| 部件面板拖入部件 | 新增 `attach_part` 节点（parent 挂到指定父节点） |
| 拖动/旋转/缩放部件 | 更新该节点 `location` / `rotation_deg` / `scale` |
| 删除部件 | 删除节点，下游重接到其输入 |
| 选面开槽 | 新增 cutter `primitive` + `boolean_subtract` 节点 |

范围线：

- 手动操作只作用于 **attach_part 节点与开槽**；船体基元（primitive）的参数编辑走文字指令 / `--node`，不在视口内手编（避免编辑器滑向 CAD）
- 缩放沿用 attach_part 现有的 uniform scale，不做非均匀缩放

## 4. 吸附系统（部件吸附点 + 面吸附结合）

- 部件在 `parts/index.json` 声明吸附点（位置 + 法线）。拖 A 靠近 B 的吸附点：位置吸附 + **自动对齐朝向**（A 安装轴对齐吸附点法线）
- 对船体/任意几何做面吸附：射线命中面 → 吸附到表面 + 对齐面法线
- 优先级：吸附点 > 面吸附。吸附命中时高亮预览，松开鼠标落定

## 5. UI

- 左侧部件面板：缩略图列表（`GET /api/parts` 返回部件元数据 + GLB）
- 视口：three.js TransformControls（移动/旋转/缩放三模式切换）+ 射线拾取选中；选中高亮；Delete 键删除
- 现有指令框、焦点节点下拉、设置面板全部保留不动

## 6. 错误处理

- `/api/edit` 校验失败（悬空引用、成环、未知部件）：结构化错误返回，树不变，前端提示
- 构建失败：沿用现有错误透传

## 7. 测试

- 服务端：`/api/edit` 每种操作的树变更正确性、校验拒绝路径、增量构建断言（改 location 只重算下游子树）
- 吸附纯函数：吸附点命中/优先级/朝向对齐的 pytest 覆盖
- 手动验收：拖入 → 吸附 → 移动 → 开槽 → 导出 GLB；再用文字指令让 AI 修改手动摆的部件（验证手动/AI 统一）

## 8. 不做（YAGNI）

- AI 演算补形（下一迭代）
- 外部模型导入（子项目 3）
- 非均匀缩放
- primitive 视口内编辑
- 多选
- 撤销/重做（本期以"再改回去"顶着；DAG 重放留待后续）

## 9. 验收标准

1. 视口内完成：拖入 ≥2 个部件（均触发吸附）→ 移动/旋转/缩放其一 → 删除其一 → 对船体开槽 → 导出 GLB，全程无文字指令
2. 对同一 session 发文字指令"把刚才那个炮塔移到左舷"，AI 正确识别并修改手动摆放的节点
3. 现有全部测试通过（kernel 64 + orchestrator 83+新增）
